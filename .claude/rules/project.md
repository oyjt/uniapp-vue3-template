# 项目开发规范

## 导入规范

- 使用路径别名 `@` 指向 `src` 目录

## 代码质量

- 编写整洁不冗余、可读性强的代码，始终提取共用逻辑
- 编写对开发者友好的注释
- 代码必须能够立即运行，包含所有必要的导入和依赖
- 尽量避免使用兼容性不好的 JS、CSS 语法，使用时必须提供相应的注释
- 参考项目已有代码的编码风格
- 兼顾 H5、小程序、App 多端兼容性，通过 `#ifdef` 和 `#endif` 条件编译处理平台差异

## 代码检查

- 使用 ESLint 进行代码校验与格式化
- 禁用 Prettier 进行代码格式化

## API 模块结构

每个模块包含 `index.ts`（请求函数）和 `types.ts`（类型定义），统一从 `src/api/index.ts` 导出。

## 其他

- 优先使用现有第三方依赖，避免重新发明轮子
- 保持目录结构清晰，遵循现有目录规范
